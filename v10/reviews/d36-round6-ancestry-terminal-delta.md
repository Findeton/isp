## 2. Round-five major disposition

The rejected implementation stored transaction actors in a tuple and used
`envelope.target_index` as the tuple subscript.  A participant could locally
accept a valid carrier-derived attempt at nominal address two, but ordinary
transport of its response tried to read tuple element two.  With only one
transaction actor present, transport crashed.  A12 therefore proved only the
participant handler cell, not a realizable actor world or a closed ledger.

The repaired implementation makes the physical transaction registry a finite
set serialized in canonical structural-attempt order.  Live operations use:

```text
transaction_actor(world, attempt_id)
replace_transaction(world, updated attempt)
services: ("T", structural attempt ID, mailbox position)
response transport: envelope.attempt_id -> addressed transaction actor
```

Tuple position no longer appears in transaction delivery, transaction
servicing or actor replacement.  The nominal integer `tx_index` remains in
typed records and envelopes and in the deliberately dense frozen-reference
adapter.  That adapter now explicitly requires a complete nominal fixture and
orders it by the actors' declared nominal indices; it is not used by the
sparse physical gate.

The registry rejects duplicate structural attempts and the ledger validator
rejects duplicate nominal transaction addresses.  Canonical tuple order is a
deterministic serializer, not an address or a physical construction order.

**Disposition:** closed.
