## 1. The question, and what it is asked of

The transport geometry of this programme has been measured on two bases. Base
1 has two qubit wings and a 36-configuration carrier; base G has two qutrit
wings and an 81-configuration carrier. They share no rotation, no
preparation, no completion and no carrier dimension, and they were built years
of ledger apart. What they share is a wing count.

That is not a small thing to share, because the wing count *is* the symmetry
group. With two wings the declared symmetry is a single involution $W$;
$\langle W\rangle$ has order two, is abelian, and every commutator
$[W, u]$ satisfies $W [W,u] W = [W,u]^{-1}$, so $\langle W, [W,u]\rangle$ is
dihedral *by algebra*. XBA derived that relation symbolically and measured it
on eight instances. Its corollaries — the order law, the forcing of the
class-count profile — are corollaries of a **two-element group**.

So the natural question is not whether the law is *true*. It is what the law
is a law **of**. This unit answers by building the first base designed to
break the answer if it is going to break:

- **three wings**, so the wing symmetry group is $S_3$: non-abelian, with
  elements of order three, and containing the two-wing case as a subgroup;
- **the six leg-orders as frames**, so triple overlaps are what the base *has*
  rather than what an extension declares — COC had to declare a 216-element
  extension scope to obtain a non-abelian chart-generating group, and here the
  $j_0$ filter admits $S_3$ natively;
- **multipartite preparations**, so GHZ-class and W-class states — which
  differ in exchange structure in ways no bipartite $\psi$ can — can be
  compared at identical declarations.

Three things make the comparison meaningful and each is a declaration of this
unit. The machinery is written **generic in the wing count**, and what that
buys is stated at its measured strength: the same code at two wings anchors
the wing-count-generic layer — legs, record injectivity, admission rules, walk
enumeration, orientation, reduction, scope, read time, link naming — at the two
defect orders that species realises, and it does **not** reach the loci the
three-wing findings live on. At two wings the symmetry group is $\mathbb Z/2$,
so there are no non-involution cells at all; there are two frames rather than
six, so no triangle census; and GHZ/W does not exist below three wings. Each
of the twelve axis-specific falsifiers is caught by internal gates with no
external-anchor coverage, and §8.2 says per axis which control reaches which
claim. Every link carries a $\psi$-independent name, so "the same loop at two
preparations" is a statement about names. And every census names its routes
and what their agreement does and does not establish (§11.8).

## 9. The gauge layer and the symmetry self-test

The declared switching group assigns a sign to each link, so a closed loop's
matrix is defined only up to a sign. Both of this unit's holonomy readings are
invariant under that action, and RUNBOOK §14 requires the instrument to
measure the invariance under the symmetry's **own** action rather than under a
wholesale replacement.

Swept over all **150** single-link switchings against all **121**
cycle-basis generators — 18,150 cells:

| measured | value |
|---|---|
| Born-shadow readings that moved | **0** |
| permutation parts that moved | **0** |
| generators whose **sign** the switching flips | **366** — the sweep is not vacuous |
| generators **rebuilt from their own directed link path** and matching the spanning-tree construction | **121 / 121** |
| with every link switched: rebuilt holonomy = unswitched × the parity read independently off the path | **121 / 121**, of which **84** have negative parity |
| fresh-mode cache hits | **0** of **16** lookups |
| cache entries primed / reads that returned a stored value | **8** / **8** |
| fresh requests for a key already in the cache | **8** |

The two rebuild clauses are the RUNBOOK §14 addendum applied to this
instrument's own comparator: each generator is reconstructed by the
walk-holonomy routine from its directed link path — code that shares nothing
with the spanning-tree construction that produced it — and the sign path is
then *exercised* rather than merely declared, by switching every link and
gating the result against a parity read independently off the path length.

The self-test evaluates **fresh**: the cache is primed with the very keys it
will request, the priming phase's own re-read is counted so the read path is
measured to work, the fresh-mode hit count is gated at zero, and the count of
fresh requests for a key that *is* in the cache is gated **non-zero** — zero
hits of zero lookups would be vacuous.
